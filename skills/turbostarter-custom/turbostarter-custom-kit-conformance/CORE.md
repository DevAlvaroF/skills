# Core kit: the kit's way

A pnpm and Turborepo monorepo: `apps/web` (Next.js), `apps/mobile` (Expo), `apps/extension` (WXT), shared code in
`@workspace/*` packages. Where the repo differs, the repo wins: it is the version you'll merge with.

- **API:** Hono modules under `packages/api/src/modules/<module>/router.ts`, mounted in `packages/api/src/index.ts`
  under `/api` and served by `apps/web/src/app/api/[...route]/route.ts`. Guard routes with the middleware in
  `packages/api/src/middleware.ts` — `enforceAuth`, `enforceAdmin`, `enforceUserPermission`,
  `enforceOrganizationPermission`, `enforceMembership` — and validate input with its `validate`. Every app calls the
  API through the typed client (`hc<AppRouter>` in each app's `src/lib/api`) and `handle` from
  `@workspace/api/utils`, never a hand-written `fetch`.
- **Tenancy is in the app, not the database:** there is no RLS. Organizations come from Better Auth's organization
  plugin; tenant tables carry `organizationId`, every query filters by it, and the route proves access with
  `enforceOrganizationPermission` or `enforceMembership` before touching data. Roles and permissions live only in
  `packages/auth/src/rbac/`; a role check elsewhere re-implements them. Billing is owned by a `referenceId` that is a
  user or an organization, checked on the server.
- **Auth:** `packages/auth` (`src/server.ts`, clients in `src/client/{web,mobile}.ts`); one client per app.
- **Schema workflow:** app tables in `packages/db/src/schema/<name>.ts`, exported from its `index.ts`, then
  `pnpm with-env pnpm -F @workspace/db db:generate` and `db:migrate`. `schema/auth.ts` is generated by
  `packages/auth`'s `db:generate` from the Better Auth config: change the config, never the file. Never edit an
  applied migration under `packages/db/migrations/`, nor its `meta/`.
- **Billing:** the provider is chosen by the re-export in `packages/billing/web/src/providers/index.ts` (mobile:
  `packages/billing/mobile`); call the billing package, never a provider SDK from app code.
- **Other primitives:** `logger` from `@workspace/shared/logger`, never `console.log` in server code; `sendEmail` from
  `@workspace/email/server` with templates in `packages/email/src/templates/`; i18next translations in
  `packages/i18n/src/translations/<locale>/` for every visible string; UI from `@workspace/ui-web` /
  `@workspace/ui-mobile` entry points, never deep paths; env through each app's `env.config.ts` (envin); feature
  flags through `@workspace/flags-*`; analytics and monitoring through their `-web`/`-mobile`/`-extension` packages.
- **Web:** Next.js 16 — `proxy.ts`, not middleware; RSC by default, `'use client'` only when needed; pages under
  `apps/web/src/app/[locale]/`, personal under `dashboard/(user)`, organization under `dashboard/[organization]`;
  feature UI in `apps/web/src/modules/<feature>/`.
- **Mobile and extension:** see `/turbostarter-custom-mobile-app` and `/turbostarter-custom-extension`. Without them:
  both reach data only through the web app's `/api` with the typed client; neither holds its own server logic.
- **Upstream-owned:** `packages/**` and `tooling/**`, and `turbo/generators/**`. `apps/**` is the app's starting
  point, and `apps/*/src/config/`, navigation and `packages/i18n/src/translations/` are meant to be edited.
- **Generated:** `packages/db/src/schema/auth.ts`, applied migrations and `meta/`.
